# Translation resources

Marketing and app UI copy lives in `apps/web/src/locales/en.json` and `zh.json`. Existing marketing keys remain supported; app/page keys use the `ui.<component>.<message>` convention. Components call `uiText` for text and `uiValue` for structured content or message groups. Dynamic values use named `{{placeholders}}` so translations can reorder them. Do not add English/Chinese ternaries or translation dictionaries to components.

`apps/web/src/i18n.ts` registers language metadata (code, native display name, formatting locale, HTML language) and resource imports. Add a locale file based on the English key structure, translate its values, import/register it, and add its metadata there. Language menus use that registry. Keep keys stable when editing copy. English is the fallback. Public approved multilingual content retains its existing English/Chinese requirements and can carry additional language entries; unavailable translations fall back to English.

Saved customer/profile language tags accept bounded language codes rather than an English/Chinese enum. API validation still rejects malformed tags. Register a language in the frontend before offering it in menus.

Use `localeFor` for dates/numbers, `languageName` for language names, and `publicText` for multilingual content records. Keep customer-entered names, addresses, business records, and proper names separate from translated UI copy.

Checks in `tests/translation-resources.test.mjs` require matching resource structures/interpolation names and reject embedded Chinese alternatives or dictionaries in TSX components. Run the appropriate browser checks as well: resource parity cannot prove correct rendering or translation meaning.

Language uses URL query parameters (`?lang=en`, `?lang=zh`). A valid URL parameter overrides storage; unlocalized/unsupported links normalize to the stored supported language or English. Internal link targets retain language, as do canonical/legacy routes and sign-in return links. The route parser keeps language separate from business-filter queries so a language-only change does not remount forms or reset filters.
